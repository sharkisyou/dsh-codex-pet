# 桌宠窗口拖动管线（手动 setPosition + 缓存锚点）

状态：accepted（扩展 ADR 0001「桌宠-桥接架构」的宠物窗交互面）

## 背景

宠物窗透明置顶、无标题栏。拖动最初走 Tauri 的 `startDragging()`（原生标题栏拖动循环），
2026-09-07 实测会触发 Aero Shake（快速来回甩动宠物 → Windows 最小化其他所有窗口）与
边缘贴靠/顶部最大化，因此改为**前端按帧 `setPosition`** 手动拖动。

改完之后用户反馈"有的时候移动不了桌面宠物"。2026-09-10 用脚本化鼠标驱动实机桌宠
（DPI-aware 的 `SetCursorPos`+`mouse_event`，轮询窗口矩形取真值），定位到三处时间竞态：

1. **起拖锚点现查 IPC**：`pointerdown` 里 `Promise.all([outerPosition(), 显示器枚举])` 才设锚点，
   而锚点就绪前的 `pointermove` 被 `if (dragAnchor === null) return` 丢弃，且 `dragStarted`
   只能由"锚点就绪**之后**到达的 pointermove"置位 → 手势若整段落在该窗口内即完全空操作。
   实测锚点延迟：保温态中位 28ms、常态 20–40ms、冷调用长尾 119ms；单帧快甩（按下 +15ms
   位移、+25ms 松手）**4/4 次零位移**，而日志对时显示锚点在 +20~22ms 才就绪。
2. **`pointerup` 不补帧就清状态**：`pointermove` 只排一个 rAF，`resetDrag` 把 `dragLatest`
   置 null 后 `applyDragFrame` 早退 → 最后一次移动的位移整段丢掉。实测丢帧窗口 ≈10–20ms
   （rAF 周期）：单帧位移 + 5/10ms 内松手 = 0px，≥20ms = 精确；多报告手势固定丢最后一步
   （160px 甩动丢 40px、36px 轻推丢 6px）。
3. **锚点串台**：异步锚点回来时只看"还按着且未起拖"，没校验是哪一次按下 → 上一次按下的
   迟到锚点会被套用到下一次按下（winX/screenX 不匹配 → 位移跳变）。
   （实机 14 次定向尝试未复现，属低概率隐患：后发的锚点通常会覆盖先发的。）

同期实测排除的假设：**与 pet server 连接无关**——拖动路径不经过 WS；停掉 pet-server 后
慢拖仍精确跟手、单帧快甩仍 0 位移、轻推仍丢 6px，与在线一致；服务端广播负载 0 vs 4 条/2s
时拖动中位帧间隔均为 17ms（满帧）。

## 决策

1. **拖动仍由前端按帧驱动**（不用 `startDragging()`，理由见背景），但锚点改为**宿主缓存**：
   窗口外框坐标由 `onMoved` 事件维护（启动时预取一次），显示器矩形启动取一次 + 每次拖动
   结束后刷新。`pointerdown` 同步取锚点，缓存未命中才回退异步查询；**回退期间照常判定
   5px 阈值并记录最新光标**，锚点一到立即起拖补帧（不再依赖"之后再移动一次"）。
2. **松手/取消先同步补最后一帧再清状态**；残留的 rAF 回调空转（靠 `dragStarted` 守卫）。
   另：`pointerUp(event)` 把**松手坐标**当作最后一次移动的兜底——浏览器的输入合并会把整段
   位移并进 up 事件（一个 `pointermove` 都不派发；实机快甩 3 次里出现 1 次），不兜底那次
   手势仍是整段失效。
3. **锚点带按下序号**：异步结果仅在序号一致时生效；另在"首个应用帧之前"用异步结果校正
   陈旧缓存（迟到即忽略，绝不造成拖动中跳变）。
4. **状态机独立成模块** `src/drag-controller.ts`，依赖全部注入（窗口位置/显示器/量测/
   `setWindowPosition`/帧调度/日志）→ 可在 node:test 里用假窗口 + 手动帧泵覆盖上述竞态。
5. **埋点补全**：拖动起止写 scope `drag` 的 `start`（锚点来源、起拖延迟 ms、dpr、显示器数）
   与 `end`（末位置 + 应用帧数）、`anchor-failed`/`anchor-refreshed`；软钳制沿用 scope
   `clamp` 的既有行格式。原先拖动路径几乎没有埋点，是这次排查的主要障碍。

## 关键取舍

- **缓存锚点 vs 每次现查**：缓存让起拖同步（零等待），代价是按下瞬间读到的位置可能旧一个
  `onMoved` 往返（毫秒级）；用"首帧前的异步校正"兜住，且该校正永不造成拖动中跳变。
  位置缓存不会有更大偏差：窗口每次移动都伴随 `onMoved`，而拖动中的移动由本管线自己产生。
- **补帧走同步路径**：跟手性优先于"每帧只 setPosition 一次"的纯粹性——最后一帧必须落地。
- **不做的事**：不改 Rust（拖动全在前端）；不引入 `setIgnoreCursorEvents`/点击穿透（另见
  `.scratch/pet-clickthrough/`，wontfix）；`applyZoom` 每次广播都 `setSize` 的无谓 IPC
  留作后续优化（实测未影响帧率）。
