# 桌宠"防拖出屏幕丢失"位置钳制

## 背景与问题

宠物窗口可被手动拖到屏幕边缘外（窗口大部分是透明边距，拖透明区时精灵本体先出屏），
拖丢后用户找不回来。同类存量坏档：分辨率变更/显示器拔掉后，旧存档坐标落在可视区域外，
开机即丢。

## 决策（2026-09-08，用户拍板三个参数）

1. **允许宠物坐任务栏** → 钳制边界用显示器**完整边界**（`availableMonitors()` 的物理矩形），
   不用排除任务栏的工作区。
2. **拖动中允许精灵藏到只剩最小可见条** → 拖动中用**软钳制**：精灵 bbox 在显示器并集内
   保持至少 32×32 物理像素可见（保留贴边玩法），不做完整包含。
3. **支持多显示器** → 边界源 `availableMonitors()`（物理坐标精确），并集包围盒为软钳制总界；
   硬钳制目标 = 恢复坐标所在的显示器，都不命中则主显示器（`primaryMonitor()` 排到首位）。

## 设计要点

- **钳制参照物是"精灵 bbox"而非窗口矩形**：窗口大部分是透明边距，"窗口可见"≠"宠物可见"。
  bbox 由 `.pet` 元素 `getBoundingClientRect()` × devicePixelRatio 量测（CSS 布局是唯一真相源，
  不复制 bottom:44px / 居中公式）。注意：与 `.scratch/pet-clickthrough/` 的像素级 bbox 管线不同，
  这里用稳定的元素矩形——钳制边界随动画帧抖动反而怪异；该特性的点击穿透部分已 wontfix。
- **两种强度分开**：
  - 软钳制 `clampSpriteMinVisible`（拖动 `applyDragFrame`）：并集包围盒内保 32px 可见条。
    拖动中窗口始终包含光标（数学保证），不可能整体丢失，软钳制只防精灵大半被藏。
  - 硬钳制 `clampSpriteFullyVisible`（启动/设置恢复 `applySettings` 的 positionRestored 分支）：
    精灵 bbox 完整拉回所在显示器，治愈存量坏档；显示器比精灵还小时 bbox 居中。
- **纯函数** `src/window-clamp.ts`：零 Tauri/DOM 依赖，坐标全部物理像素；`monitors=[]` 时 no-op
  （浏览器预览/查询失败退化为旧行为）。
- **量测时机**：拖动在 pointerdown 并发取 `outerPosition()+outerSize()+monitors`，锚定时量一次
  bbox 复用（拖动中窗口尺寸/缩放不变）；恢复在 monitors 查询返回后量（IPC 有序保证 setSize
  已生效）。
- **权限**：`core:window:default` 已含 `allow-available-monitors` / `allow-primary-monitor` /
  `allow-outer-size`（tauri 2.11.5 实查 permissions/window/autogenerated/reference.md），
  capabilities 无需改动。
- **诊断日志**：scope `clamp` 写 `%USERPROFILE%\dsh-pet.log`——monitors 快照、恢复钳制前后
  坐标、拖动软钳制实际生效时（不刷屏）。

## 验证记录（2026-09-08）

- `tsc --noEmit` 通过；desktop-pet 包测试 98 项（含新增 17 项）通过。
- **硬钳制端到端实测**：经 server WS API 写入坏档坐标 (100000,100000)（注意：settings 的
  source of truth 是 pet server 内存，直接改 settings.json 文件会被内存值覆盖，无效），
  重启后日志显示恢复收到 (100000,100000) → monitors 1920×1200@dpr1.25 → box
  offset(64.5,68) size(216,234) → clamped(1639,898)；精灵 bbox 右缘 1919.5≈屏宽、底缘 1200
  =屏高（坐任务栏）；settings 被 onMoved 写回 (1639,898)——坏档治愈闭环。视觉验证精灵完整。
- **软钳制待用户手工验证**（WSL 无法合成鼠标输入，见交接文档）：拖宠物到屏幕边缘，
  应保留约 32×32 可见条；斜对角拖出虚拟桌面亦然。
